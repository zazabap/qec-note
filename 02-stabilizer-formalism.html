The stabilizer formalism

Part 1 built codes one stabilizer at a time. Section 4 turns the recipe into a framework: a code is a commuting set of Pauli operators, its logical qubits are what those operators leave free, and the syndrome is a list of commutation signs. This part covers the framework and its smallest example; part 3 uses it to correct errors. The interactive figure is at the end.

Roffe §4

The [[n, k, d]] stabilizer code

A register of \(k\) data qubits is entangled with \(m = n - k\) redundancy qubits to form \(\ket\psi_\L\) (paper's figure 4), and each of \(m\) stabilizers \(P_i\) is measured with the ancilla circuit of part 1:

\[ E\ket\psi_\L\ket0_{A_i} \;\longmapsto\; \tfrac12(\I^{\otimes n} + P_i)\,E\ket\psi_\L\ket0_{A_i} + \tfrac12(\I^{\otimes n} - P_i)\,E\ket\psi_\L\ket1_{A_i} . \qquad\text{(eq. 29)} \]

Ancilla \(A_i\) reads 0 if \(P_i\) commutes with \(E\) and 1 if it anticommutes, and two Pauli strings anticommute exactly when they differ, both non-trivially, on an odd number of qubits. The \(m\) bits form the syndrome \(S\). Designing a code means choosing stabilizers that anticommute with the errors to be caught.

Roffe §4.1

The stabilizer group

The stabilizers must be Pauli operators that fix every code state and commute with one another, so that they can be measured in any order:

\[ \mathcal S = \bigl\{ P_i \in \mathcal G_n \;\big|\; P_i\ket\psi_\L = (+1)\ket\psi_\L\ \forall \ket\psi_\L,\ [P_i, P_j] = 0\ \forall i, j \bigr\}, \qquad \mathcal S = \langle G_1, G_2, \ldots, G_m \rangle . \qquad\text{(eq. 30, 31)} \]

Products of stabilizers are stabilizers, so only a minimal generating set is measured: \(\langle Z_1Z_2, Z_2Z_3\rangle\) for the three-qubit code, not also \(Z_1Z_3 = (Z_1Z_2)(Z_2Z_3)\). Each independent generator halves the space, so \(m = n - k\) generators leave a \(2^k\)-dimensional codespace.

Roffe §4.2

Logical operators

An \([[n,k,d]]\) code has \(2k\) logical operators \(\bar X_i, \bar Z_i\) that act on the encoded qubits without decoding. Each commutes with every stabilizer, so it maps the codespace to itself, and each pair anticommutes, \(\{\bar X_i, \bar Z_i\} = 0\), as the single-qubit \(X\) and \(Z\) do. Multiplying a logical operator by a stabilizer gives another representative of the same logical operator, \(\bar L P_j\ket\psi_\L = \bar L\ket\psi_\L\). The distance \(d\) is the weight of the lightest representative of any non-trivial logical operator.

Roffe §4.3

The [[4,2,2]] detection code

The smallest code that notices both \(X\) and \(Z\) errors encodes two qubits in four, with codespace

\[ \ket{00}_\L = \tfrac{1}{\sqrt2}(\ket{0000} + \ket{1111}),\quad \ket{01}_\L = \tfrac{1}{\sqrt2}(\ket{0110} + \ket{1001}),\quad \ket{10}_\L = \tfrac{1}{\sqrt2}(\ket{1010} + \ket{0101}),\quad \ket{11}_\L = \tfrac{1}{\sqrt2}(\ket{1100} + \ket{0011}), \qquad\text{(eq. 32)} \]

and stabilizers \(\mathcal S = \langle X_1X_2X_3X_4,\ Z_1Z_2Z_3Z_4 \rangle\). Every single-qubit \(X\) anticommutes with \(Z_1Z_2Z_3Z_4\), every single-qubit \(Z\) with \(X_1X_2X_3X_4\), and \(Y\) with both, so every single-qubit error is detected (table 3). The syndrome depends only on the kind of error, not the qubit, so nothing can be located. A choice of logical operators is

\[ \bar X_1 = X_1X_3,\quad \bar Z_1 = Z_1Z_4,\qquad \bar X_2 = X_2X_3,\quad \bar Z_2 = Z_2Z_4 , \qquad\text{(eq. 33)} \]

all of weight two, so \(d = 2\): a detection code. Two errors with the same syndrome differ by a logical operator, for example \(X_1X_2 = \bar X_1\bar X_2\) up to a stabilizer, which is exactly why undoing the wrong one would corrupt the data.

Ordering. Table 3 lists \(X\) errors with syndrome 10 and \(Z\) errors with 01, which means \(Z_1Z_2Z_3Z_4\) is measured first, as in the paper's figure 5, although the text writes \(\langle X_1X_2X_3X_4, Z_1Z_2Z_3Z_4\rangle\). The figures below measure \(Z_1Z_2Z_3Z_4\) first so that their syndromes match table 3.

Roffe §4.4

Encoding by projection

A codeword can be prepared without a bespoke circuit by projecting onto the \(+1\) eigenspace of every generator,

\[ \ket0_\L = \frac1N \prod_{P_i \in \langle\mathcal S\rangle} (\I^{\otimes n} + P_i)\,\ket{0^{\otimes n}}, \qquad \ket{00}_\L = \tfrac{1}{\sqrt2}(\I^{\otimes4} + X_1X_2X_3X_4)(\I^{\otimes4} + Z_1Z_2Z_3Z_4)\ket{0000} = \tfrac{1}{\sqrt2}(\ket{0000} + \ket{1111}), \qquad\text{(eq. 34, 35)} \]

and the other codewords follow by applying logical \(\bar X\) operators. In hardware the projection is the syndrome-extraction circuit run on \(\ket{0^{\otimes n}}\); each ancilla then reads 0 or 1 with equal probability, as eq. 36 shows for \(X_1X_2X_3X_4\), and a 1 is fixed by an operator that anticommutes with that stabilizer only.

Eq. 34 fixes the codespace but not, in general, the logical value; for the \([[4,2,2]]\) code the two coincide. Part 3 shows a code where they do not.

Interactive figure

Part A.1 is the circuit of the paper's figure 5: an encoder for two data qubits, the error, and the measurement of \(Z_1Z_2Z_3Z_4\) and \(X_1X_2X_3X_4\) with one ancilla each; step through it gate by gate. Click a qubit to cycle through \(X\), \(Z\) and \(Y\) errors, or click a table row; the parts share one error. The bars are drawn in the code's own basis: the codespace \(\C\) in its logical basis \(\ket{j}_\L\), and the error space the syndrome points to as \(R\cdot\C\), where \(R\) is the lightest error with that syndrome. So the bars show what the error did to the encoded information: identical to the input when undoing \(R\) would recover it, visibly changed when it would not. Try \(X_1\), then \(X_2\): same syndrome, different logical content. \(Y\) is applied as \(ZX = iY\); the global phase is invisible.
